# 아키텍처

CITY//SHIFT는 **서버 없이 동작하는 단일 HTML 파일**입니다. 분석은 미리 Python과 DuckDB로 끝내고, 결과 데이터와 원천 관측 전체를 페이지 안에 넣어 배포합니다. 브라우저는 계산된 값을 그리고 원천값을 조회만 합니다.

기준: Discovery r5.1 · 유지보수판 r5.1.1 · `site/index.html` SHA-256 `b5a8d846…c1ae121` (이전 배포본: 커밋 `f301a07`, `92d28518…afe7cff`)

## 1. 전체 구조

```
 부산교통공사 CSV 2개 (2025 UTF-8, 2026 CP949)
          │
          ▼
 ① 원천 적재 ─ DuckDB: raw_wide · hourly · special_days · hourly_flag
          │
          ▼
 ② 공개 계산용 DB 복사 ─ 위 4개 테이블만 (외부 제한 자료가 섞일 수 없음)
          │
          ├─► code/build_public_r1.py ──────► data/a, data/b, data/catalog
          ├─► code/build_station_profiles.py ► data/station
          ├─► code/check_public.py ─────────► CHECK_RESULT.txt
          │
          ▼
 ③ 역 성격: 지표 계산 → 태그 → 문구 → 원천 재계산 검산 → 화면용 JSON
          │
          ▼
 ④ 화면 빌드: 공개 CSV + 원천 아카이브 + 역 성격 + 화면 소스
          │
          ▼
 site/index.html   ◄── 저장소 루트 index.html이 이 주소로 이동
```

설계 원칙

- **공개 계산은 별도 DB에서 합니다.** 원천 승하차와 특수일 4개 테이블만 복사한 DB에서 계산하므로 공개하지 않는 외부 자료가 결과에 섞일 수 없습니다.
- **판을 덮어쓰지 않습니다.** 화면은 r3 → r4 → r5 순서로 이전 판 위에 쌓아 만들고, r5 빌드는 입력인 r4 파일의 해시가 승인본과 같을 때만 실행됩니다.
- **화면은 데이터를 다시 계산하지 않습니다.** 판정과 집계는 모두 ①~③에서 끝나고, 페이지는 결과를 그립니다. 예외는 하루 중 비중(평균 ÷ 하루 평균)처럼 표시용 나눗셈뿐입니다.

## 2. 배포 페이지

| 항목 | 내용 |
|---|---|
| 파일 | `site/index.html`, 4,707,157바이트, 1개 파일 |
| 서버 | 필요 없음. `file://`로도 열림 |
| 외부 요청 | Google Fonts(Nanum Gothic, Manrope, DM Mono)만. 실패하면 시스템 글꼴로 표시 |
| 루트 이동 | 저장소 루트 `index.html`이 `site/?v=r5-1-1`로 이동하면서 주소의 `#…` 부분을 유지 |

### 2.1 내장 데이터

| `<script>` id | 내용 | 출처 |
|---|---|---|
| `cs-data` | A 목록(주요 50·특별한 날짜 20·감소 20, 도시 전체 5), B 행사 18건·연도 비교 3건 | `data/a`, `data/b` |
| `cs-raw` | 원천 관측 112 × 638일 × 24시간 × 승하차, gzip → base64 | 원천 CSV |
| `station-data` | 112개 역 코드, 역 프로필 | `data/station` |
| `persona-data` | 역 성격 112개(태그·문구·연결) | 역 성격 처리 결과 |

### 2.2 원천 아카이브 풀기

- 페이지를 열면 `DecompressionStream('gzip')`으로 원천 관측을 풉니다. 준비가 끝나면 `window.CS_RAW_STATE`가 `'ready'`가 됩니다.
- 조회 함수: `window.CS_RAW_ROWS(역코드, 'YYYY-MM-DD')` → 그날 24개 시간대의 승차·하차 배열.
- `DecompressionStream`이 없는 브라우저에서는 상태가 `'error'`가 되고, 탐험 그래프 자리에 "이 브라우저에서는 내장 원천값을 풀 수 없어요…" 안내가 나옵니다. 성격 카드, 단서, A·B 화면은 그대로 동작하며 원천 조회는 CSV 불러오기로 대체됩니다.

### 2.3 디자인 체계

- **지층 은유:** G 지상 / B1 관측 / B2 근거 / B3 미지. 홈 하단 띠, 단서 창의 칸 이름, 이야기 구역에 같은 이름을 씁니다.
- **색:** 짙은 남색(`--night #09182A`) 바탕, 노랑(`--amber #FFD36B`) 강조, 분홍(`--pink #C31B64`)은 '그날 관측'과 변화.
- **글꼴 역할:** Nanum Gothic 본문, Manrope 제목, DM Mono 영문 정보 라벨.
- **형태:** 각진 모서리, 단색 입체 그림자, 모노 라벨. 도시 단면 일러스트는 원본 SVG입니다.

## 3. 화면과 주소

해시 주소로 한 번에 한 화면만 보여 줍니다. 뒤로/앞으로 이동과 링크 공유가 됩니다.

| 주소 | 화면 |
|---|---|
| `#/` | 처음 |
| `#/explore?s=<역코드>&d=<YYYY-MM-DD>&g=<b\|a>&h=<0~21>` | 탐험하기 |
| `#/stations` | 역 성격 112 |
| `#/library` | 전체 기능 |
| `#changes` | A 변화 목록 |
| `#events` | B 행사 분석 |
| `#explore` | 원천 관측 · CSV |
| `#profile` | 역 프로필 |
| `#rivals` | 두 역 비교(RIVALS) |
| `#g-surface` · `#lv1` · `#scanner` · `#lv2` · `#lv3` · `#change` | BUSAN BELOW 이야기(도시 단면, 스크린도어, 시간 스캐너, 근거층, 미지층, 대표 변화 상세) |
| `#about` | 데이터 출처·한계 |

**탐험 주소 파라미터**

| 파라미터 | 뜻 | 잘못된 값 |
|---|---|---|
| `s` | 역 코드(112개 중 하나) | 기본 역으로 |
| `d` | 날짜 2025-01-01 ~ 2026-09-30 | 기본 날짜(마지막 평일)로 |
| `g` | `b` 승차, `a` 하차 | 기본값으로 |
| `h` | 05시부터 센 시간 칸 22개. 0 = 05–06시, 3 = 08–09시 … 19 = 자정–01시, 21 = 02–03시 | 기본값으로 |

없는 주소는 처음 화면으로 갑니다. `#/…` 주소는 r5 탐험 셸, `#이름` 주소는 r4에서 넘어온 심화 화면을 열며, 심화 화면 위에는 '← 탐험으로 돌아가기' 띠가 붙습니다.

**탐험 화면 배치**

- PC: 왼쪽 큰 칸에 역 선택 → 그래프 → '다음엔 어디로?', 오른쪽에 성격 카드와 단서(스크롤을 따라옴).
- 모바일: 역 선택 → 성격 → 그래프 → 단서 → 다음 선택 순서. 화면 아래에 처음·탐험하기·역 성격·전체 기능 탭.

## 4. 공개 데이터 생성

`code/`에 있는 파일입니다.

| 파일 | 역할 |
|---|---|
| `pub_common.py` | 공통 함수: 공개 계산용 DB 복사, 노선 그래프·정거장 거리, 기준선 SQL, 이상 셀·역 사건, 앵커 묶기 |
| `build_public_r1.py` | A 목록·구성 역·시간대별 관측과 평소, 도시 전체 사건, 분석 일관성(기준 변형 7개), 외부 근거 연결, B 일별·단계·시간 구간·연도 비교 |
| `evidence_map_public.csv` | A 사건과 외부 사실의 연결표 |
| `build_station_profiles.py` | 역 목록, 역 프로필(평일/주말 시간대 평균, 정점, 주말/평일 비율) |
| `check_public.py` | 공개 폴더 검사(허용 목록, 금지 열·문자열, 키·개인 경로, 합계 일관성, 원천 대조, 배포본 내장값 대조) |

실행 순서(원 작업 폴더 기준):

```bash
python3 -I src/public/build_public_r1.py
python3 -I src/public/build_station_profiles.py
python3 -I src/public/check_public.py
```

입력은 원천 CSV를 적재한 DuckDB 파일(`data/cityshift.duckdb`)입니다. 이 파일을 만드는 적재 단계(원천 CSV 읽기, 특수일 표, 기준선 표)와 원천 CSV는 이 저장소에 없습니다. 따라서 **이 저장소만으로는 공개 데이터를 처음부터 다시 만들 수 없습니다.** 결과의 정확성은 `CHECK_RESULT.txt`의 원천 대조 항목으로 확인할 수 있습니다.

의존성(코드 기준): Python 3, `duckdb`, `pandas`, `numpy`. 버전 고정 파일은 없습니다.

## 5. 화면 빌드

화면 빌드 코드는 공개 저장소에 포함하지 않았습니다. 구조를 이해할 수 있도록 단계만 적습니다.

| 판 | 만드는 것 |
|---|---|
| r3 | 공개 CSV와 원천 아카이브를 내장하고 A·B·원천 조회·역 프로필·RIVALS 기능을 붙임 |
| r4 | r3 기능을 유지한 채 원본 v3 디자인(색·글꼴·헤더·히어로·지층·스크린도어·시간 스캐너) 복원 |
| r5 / r5.1 | r4를 그대로 포함하고 그 위에 처음·탐험·역 성격·전체 기능 화면, 해시 라우터, 단서 창, 역 성격 데이터를 얹음. r4 스크립트는 수정하지 않음 |

r5.1 빌드는 입력 r4 파일의 해시를 확인하고, 역 성격 112개 코드가 역 목록과 같은지, A·B 건수와 638일·112개 코드가 맞는지, 화면 안 id가 겹치지 않는지 확인한 뒤 파일을 씁니다.

## 6. 공개 범위 관리

- 저장소에 올릴 파일은 `ALLOWLIST.txt`에 적습니다.
- `.gitignore`는 이 목록으로 자동 생성합니다. 전부 무시한 뒤 목록에 있는 파일만 허용하는 방식입니다.
- 파일을 추가하려면 ① `ALLOWLIST.txt`에 적고 ② `.gitignore`를 다시 만들고 ③ `check_public.py`를 통과해야 합니다.
- `check_public.py`는 허용 목록과 실제 파일이 정확히 같은지, 공개하지 않는 자료의 열·용어, 인증키·메일·로컬 경로가 없는지 검사합니다. 허용하는 파일은 텍스트 형식(csv·md·txt·py·json·html)과, 허용 목록에 이름까지 적힌 `docs/images/` 아래 PNG입니다. PNG는 서명·청크 CRC·크기(장당 1MB·합계 5MB 이하)와 허용된 청크 종류를 검사하고, 메타데이터(출처 증명 포함) 안의 문자열도 같은 금지 용어·개인정보 검사를 거칩니다.
